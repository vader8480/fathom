## Spec ambiguities / errata and how T1 resolved them

1. **Appendix C.3 erratum:** `encode("x" * 2332, "M")` cannot be version 40. The 40-M byte-mode capacity is 2331 (2334 data
   codewords, 20 header bits). T1 asserts 2331 → v40 and 2400 → `ValueError`, and does not assert 2332. W2 independently reached the same conclusion.
2. **`port-expansion.json` shape:** §4.4.3 writes `"input": {...groups...}`. T1 uses a **list** of groups (the function's input) plus a
   `"name"` per case. Labels combined with `start` are avoided (whether `labels[i-1]` uses position or number is unspecified).
3. **`ops-vectors.json` errors:** error cases carry `"error": "missing_entity"` with `expected`/`touched` = null. `del` of a missing
   entity is a no-op on the doc but still reports its ref in `touched` (touched refs are defined per op in §4.9).
4. **Patch-table golden:** all rooms, no overlay. The spare device (no ports) is a block with `sections: []`. `label`/`peer_label`
   are `null` when the port has no label. Row `medium` = port medium (equals the cable medium everywhere in the fixture). The CSV
   `room` column holds the block's room **id** (`main`): §5.8.2 only says device/port columns contain names.
5. **FR-HIST-01 "three writes → three entries":** the first write on a history-less project also records the baseline revision 1
   (§4.10). The test counts entries after a priming write.
6. **`build-notes.txt`:** required for campus (notes exist). Not required for a build that has no notes (RRC with a public URL), per
   the v0.2 semantics kept by FR-EXP-02.
7. **Role matrix:** expected roles come from the §5.2–§5.13 tables, not from the server's declarations. A mutating route that the
   spec does not name defaults to editor, a GET to viewer. The declared roles are compared to the spec too (no mismatches at finish).
8. **Body caps:** tested through `Content-Length` (§FR-SEC-02 "checked before reading"). Changing `FATHOM_MAX_UPLOAD_MB` at runtime
   is not tested because the spec does not say it is re-read per request.
9. **QR endpoint 409 `no_public_url`:** this cannot happen over HTTP, because the request's scheme and host are always known
   (FR-EXP-04 server fallback). The test checks 200 instead, plus byte equality with `qr.svg(export.device_url(public_url, n, dev))`.
10. **Lighting contribution:** DMX for auto fixtures is accepted either in `contribution["dmx"][id]` or in the overlay device's `dmx`.
11. **Dante Device Info** goes through `merge.build_overlay`, because legacy importers are lifted by the overlay (§4.11), not by `Importer.contribute`.
12. **Performance fixture:** the 150/600 doc is generated in Python (`fixture-gen.js` is JS-only). Soft timings warn above
    target, and the server-time checks fail above 1000 ms (§8.2).
13. **Chrome PDF test:** `test_report_pdf` takes about 15 s with Chrome present, so it runs only with `FATHOM_T1_CHROME=1`. Its skip reason names
    Chrome, which keeps it compliant with G1.
14. **Racks:** the device default `depth` is `full`, and a full-depth device blocks both faces (FR-RACK-02). The half-depth case sets both devices to half depth.
15. **ATEM XML (P2):** the label may be the long or the short input name (not specified).
16. **§2.3 item 9 future-import check** excludes the frozen `fathom/__main__.py`, which never had the import.
17. **Assistant notes line:** the §5.10 example text ("HDMI In 1 … embedded audio") differs from the §6.9.5 template ("<port> on
    <device> also carries <discipline> …"). The test only requires a note naming ATEM Mini and Stage Box 1 with "not patched".
