## Contract notes and small additions (no breaking deviations)

- `model-core.filterDevices` returns **device objects** (not ids). Test it with `.map(d => d.id)`.
  `filter.includeExternal: true` adds the cross-room ghosts. The extra export `externalDevices(doc, room)` covers FR-ROOM-05.
- `invertOps` keeps a deleted entity's position: the inverse of a `del` that was not last is `put`
  followed by `move` (`before` = the old next id). Undo of a delete therefore sends a `move` op (P1 in §4.9).
  W1's `apply_ops` accepts `move`. If a server ever rejects it, the undo batch is dropped and the shell resyncs.
- `diffDocs` op order: for each collection in `COLLECTIONS` order, `del` ops (a order) then `put` ops (b order); root `replace` ops come last.
- Op errors throw `OpError` with `.code` (`bad_op`, `missing_entity`). Read-only commits throw `ReadOnlyError`.
- Extra store members: `store.emit(type, detail)` (the change queue emits `saving` through it), `store.highlighted`,
  `store.setVocab(v)`, and an `error` event when an undo/redo cannot apply.
- `ChangeQueue` extras: `takeRestored()` returns ops persisted in `localStorage["fathom.pending.<project>"]`. The shell re-applies them on the fresh doc.
  Also `resync()`, `setAutosave(b)`, and events `state`, `rebased`, `problems`, `dropped`.
  Storage shape: `{"project", "items": [{"ops", "label"}]}`. Plain `{"ops": [...]}` is also read.
- ctx extras beyond §6.4: `prompt`, `openDialog`, `closeInspector`, `reload()` (resync from server), `flush()`,
  `timeTravel(rev)`, `endTimeTravel`, `restoreRevision(rev)`, `queue`, `meta`, `role`, `session`, `appRoot`, `isTimeTravel()`.
- Hash room `*` = All rooms. Selection is mirrored into `?sel=` with `history.replaceState`, so it creates no history entries.
- Debug switches: `?debug_missing_view=<key>` (search or hash query) loads a non-existent module for that view and shows the error card.
  `?smoke=1` works in the search part or in the hash query.
- Harness pages are booted by `app.js` (`<body data-fathom-harness="patchtable">`), because the app CSP forbids inline scripts.
- Renderers: `render_html(project, layout, *, nav=None, base_url="", sw=False, highlight_bridge=True)`.
  The other page renderers take an extra optional keyword `link_style="viewer"|"build"`.
  - `viewer` (default): links are relative inside the `p/<n>/…` tree (`r/<room>`, `d/<dev>`, `rooms`), so `/s/<token>/…` mirrors work too.
  - `build` is for W2: `rooms/index.html`, `rooms/<room>/index.html`, `rooms/<room>/patch.html`, `devices/<dev>.html`.
  - **W2: pass `link_style="build"` and `sw=False` from `export.write_build`.**
- Every viewer page carries the `__fathomErrors` capture and the `?smoke=1` marker. With `sw=True` it also gets the manifest link and SW registration;
  the app root comes from `base_url` via `<html data-app-root>`.
- `layout.py`: a new kind's color comes from `fathom.vocab`, and its layout heuristics use the vocab `legacy` kind.
  The key's `network` row reads the spine label when the spine is drawn. The 9 v1 kinds take the exact same path, so RRC boxes are identical (verified).

## For W3 / W4

- When you handle Cmd/Ctrl+Z, Cmd/Ctrl+Y, Esc or Delete yourselves, call `e.preventDefault()`. The shell's global undo skips events that are already default-prevented.
- The view host now has a definite height (`.app-view` is a flex column inside a `minmax(0,1fr)` grid row). Fill it with `flex:1` or `height:100%`.
- `ctx.pickPort({compatibleWith:{device, port}, room})` uses `canConnect`. If the source port is `in`, it lists outputs (candidate → source).
- Patch table split view mounts `./patchview.js` `mount(el, ctx)` in the top half (≥ 1100 px).
