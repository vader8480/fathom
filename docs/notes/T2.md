## How to run

- JS: `node --test tests/js/*.test.mjs` (or bare `node --test` from the repo root). See open question 1 about `node --test tests/js`.
- Smoke: `python3 -m unittest tests.test_frontend_smoke -v` (also passes on `/usr/bin/python3` 3.9.6). About 50-65 s; Chrome runs 4 at a time.

## Open questions

1. **G4 command on Node 26.** `node --test tests/js` (SPEC §8.1 G4) fails before any test runs: Node ≥ 22 treats the argument as a module path (`Cannot find module '.../tests/js'`) instead of searching the directory as Node 18/20 did. Making the literal command work needs a `tests/js/package.json` (`main`) or `tests/js/index.js`, neither of which T2 may create. Equivalent commands that run all 120 tests: `node --test tests/js/*.test.mjs`, `node --test 'tests/js/**/*.test.mjs'`, or plain `node --test` from the repo root. QA should use one of those; the spec could adopt `node --test tests/js/*.test.mjs`.
2. **`traceLocal` and vocab.** §6.5 `traceLocal(doc, overlay, start, opts)` has no vocab argument, but the discipline filter (§6.9.2) needs `carries()`. W3 reads `opts.vocab` and **silently ignores** `opts.discipline` when it is missing (the video trace then reaches `atem-mini:analog-in-1`). T2 passes `{vocab}` in opts. Suggest documenting `opts.vocab` in §6.5, and failing closed (or throwing) when a discipline is given without vocab.
3. **Patch-table sections for ungrouped ports.** §6.6 says "sections = consecutive port groups … title = group, else `<MEDIA.short> <In|Out|I/O>` … mixed → io". W5 (JS) and W6 (Python) both key ungrouped ports by their fallback title, so an ungrouped `in` port followed by an ungrouped `out` port gives two sections ("HDMI In", "HDMI Out") rather than one "HDMI I/O" section. T2 adopted that reading because both implementations agree and the fixture is unaffected.
4. **`ChangeQueue` restore hook.** §6.3 says the queue "restores [unsent ops] on startup". W5 loads them in the constructor but only re-queues them when the shell calls `queue.takeRestored()` (not in the contract; `app.js` calls it). So `pending` is 0 on a fresh queue until then. T2 calls `takeRestored()` when present. Suggest adding it to §6.3.
5. **Undo of a delete and collection order.** §4.9 says `put` appends new entities; strictly, undoing the delete of a middle entity would move it to the end, and FR-PV-08's deep-equal could not hold for deletes. W5's store currently preserves the original position (T2 logs this as a diagnostic). The 20-step test uses moves, renames, connects and settings only; delete undo is compared order-insensitively.
6. **`rack-core.uToY` "respects numbering".** FR-RACK-02 defines `u` as the physical RU (1 = bottom), so the drawn position cannot depend on numbering; W4 applies numbering only to `ruLabel`. T2 asserts geometry for `bottom_up` and labels for both numberings.
7. **`data-smoke` on viewer pages and `/login`.** §6.12 requires it only for harnesses and the app. Viewer pages emit it anyway; `/login` does not. For pages without it, the smoke test checks there are no "Uncaught" console lines from the app origin (Chrome `--enable-logging=stderr`), a non-empty body, and that every same-origin `script`/`link`/`img`/`iframe` URL returns 200.
8. **Perf under virtual time is vacuous.** With `--virtual-time-budget`, `performance.now()` is virtual and the harness reports `renderMs: 0`. G7 as written would always pass. T2 measures the 150/600 harness in real time through the DevTools protocol (stdlib WebSocket client) and asserts `0 < renderMs ≤ 1500`; the virtual-time dump still checks `ready`, `errors`, `cards = 150`, `wires = 600`.
9. **Patch-table filter keys.** §6.6 lists the filters (room, discipline, device text, only patched) but not the keys. W5 accepts `query`/`text`, `discipline`/`disciplines`, `onlyPatched`/`only_patched`, `includeOverlay`/`include_overlay`. T2 sends `query` and `text`.
10. **Lint scope beyond the enumerated list.** Following §2.3 item 9 ("ES2018 syntax … must run in Safari 15+"), the lint also rejects optional catch binding (ES2019), BigInt literals, `export * as ns`, hashbang, regex lookbehind (Safari < 16.4 cannot parse it) and regex flags `d`/`v`. Dynamic `import()` is allowed because FR-UX-03 requires it. No current hits.
11. **`canConnect` ok flag.** §4.4.4 does not say what `ok` is for warnings. T2 asserts `ok === (level !== 'error')` (warnings are allowed connections); W5 agrees.
