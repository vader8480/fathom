## Decisions where the spec is open

1. **Check de-duplication** (§6.9.5 step 9 says "by check id"): key is `(id, device)` for template/kind checks,
   `(id, from device, to device)` for media checks, `id` for generic checks. A template check shadows a kind check
   with the same id on the same device; the same kind check can still appear for two different devices.
2. **Notes for unpatched branches** (§6.9.5 step 8 ii): a non-candidate path whose unpatched source port sits on the
   device where it joins the suspect path (for example ATEM `hdmi-in-2`, which has no cable at all) gives no note.
   This is what keeps the fixture `notes` to the single HDMI In 1 line. The `<port>` in the note is
   `"<group> <index>"` (so "HDMI In 1"), and the discipline reads "embedded audio" when the port medium's own
   discipline differs from the traced one.
3. **`unresolved` items**: `{"text", "suggestions": [{"device", "port", "title"}], "message"}`. `message` is the
   ready-made sentence "I couldn't find 'projector 2'. Did you mean: …?". Only role phrases that match no device,
   and leftover phrases that contain a digit, are reported (this avoids noise from ordinary words).
4. **Empty question**: `assistant.answer` raises `ValueError("empty question")`. W1 should map it to 400.
5. **Suggestion keyword**: the first check with a `note` on the suggested port, then on that device, then any.
   The leading word is the port label, else the discipline capitalised.
6. **Racks**: when `depth` is missing, the placement defaults to `full`, which blocks both faces (so the rear
   elevation shows "(front)" blocks dimmed). `rack_occupancy` also returns `devices` (normalized placements)
   besides `rack/slots/collisions`. Collisions are reported once per (pair, face) at the lowest shared U.
7. **Patch table filters**: `discipline` keeps a device when its discipline or any port medium's discipline
   matches. `query` is a case-insensitive substring of id/name/manufacturer/model/sub/code. Overlay rows
   (`include_overlay`) are listed under the route's port with `source` = route `kind`. CSV `Room` = room id and
   `Dir` = section dir, because the CSV is derived from blocks only (needed for JS/server byte equality).
8. **Tracing**: a start or end given as a bare device id means "any port of that device" (handy for
   `GET …/trace?from=atem-mini`). Paths are enumerated breadth-first (shortest first, bounded at 200k
   expansions), the length level that reaches `limit` is finished, then sorted by `(len, hop refs)`.
   Device-level `dev:*` nodes are wired both ways to every port that carries the discipline (§6.9.1).
9. **DMX**: `dmx_problems` also emits `dmx_range` and `dmx_footprint_unknown`. If W1's `validate_doc` implements
   `dmx_range` itself and also calls `dmx_problems`, the warning would appear twice: W1 should rely on mine.
10. **Template checks**: resolved via `fathom.library.get_template(id, doc)`, then `doc.templates`. If neither yields a
    template with a `checks` key for `blackmagic-atem-mini-pro(-iso)`, the Appendix F.6 check is used as a built-in
    fallback, so the fixture answer stays correct before the library lands.
11. **LLM**: prior `history` (last 6 turns) is sent as chat turns before the final user message. Context is
    truncated by dropping context paths, then port lists, then hard-cutting (the suspect path is serialized first).
    Errors become `llm.error` text without URL or key.
12. **Search**: ports are searched on name/label/note only, not on the device name, so "atem" returns the device
    first and alone.

13. **Intent targets (QA fix-up 2)**: complete device names match first; then a full room name in the question
    (`chapel`, `broadcast suite`) is consumed and scopes kind words to that room (and becomes `intent.room`), so
    it never selects a device by name on its own; then role/kind words resolve to the **first** of the role's kinds
    that has devices in the room (`mains` → speakers before amps), narrowed to devices whose name carries the word
    stem (`mains` → `Main hang L/R`). Only when the room has none, other rooms are used and a note says so.
    Search-based mentions only count through name-like fields (name, id, alias, code, label, serial, ip, …) with
    every word whole or a ≥ 4-char prefix of a title word, so `black` no longer hits a Blackmagic router.
    `black` / `blank` phrases map to `no_video`.
14. **Multi-target answers**: each target gets its own best path (others become `context` paths and are appended to
    the summary), and "not patched" notes are computed against the suspect path of the same target.
15. **Device-level nodes (QA fix-up 1)**: `dev:*` is wired one way (in/io → dev:* → out/io, none for routing
    `none`); a `dev:*` or bare-id start expands to the device's inputs (upstream) or outputs (downstream).
