## Harnesses

`dev/<name>.html` loads `dev/plans/harness.js` (external module, not inline, so a
`script-src 'self'` CSP on static pages cannot block it). It:

- loads `fixture-v2.json`;
- uses `model-core.createStore` when it imports, otherwise a local §6.2 store shim
  (`?shim=1` forces the shim);
- builds a fake ctx with `api: null` and mounts the view(s);
- writes `data-smoke` when the URL has `?smoke=1`.

Extra URL flags:

| Flag | Effect |
| --- | --- |
| `?walk=1` | Runs a scripted pointer/keyboard walkthrough and writes `data-walk` with `ok`. |
| `?readonly=1` | Mounts the view read-only. |
| `?demo=1` (rack) | Seeds more racked devices. |
| `?collide=1` (rack) | Seeds a collision. |
| `?empty=1` (plan) | Starts with no seeded plans. |

The floor-plan harness seeds three plans in room `main`: Main floor (with 5 markers),
DXF fixture, and Stage.

`file://` works in Chrome only with `--allow-file-access-from-files`. Chrome refuses ES
module scripts and `fetch` from `file://` without it. Headless `--virtual-time-budget` is
unreliable for `file://` module loads; a real-time wait works.

## Interpretations and open questions

1. **Rack `u` is physical.** `u` is the lowest occupied RU with 1 = bottom (FR-RACK-02
   wording), whatever the numbering. `numbering: top_down` only changes labels (`ruLabel`).
   `uToY` therefore ignores numbering, even though §6.7 says it "respects numbering".
   W6 `racks.py` should use the same reading.
2. **Default rack `depth` is `full`.** A front device with no `depth` also occupies the
   rear face (FR-RACK-02: "full-depth blocks both faces"). The rear view draws it as
   "Rear of X" (hatched). Back-to-back mounting needs `depth: half` on both devices.
3. **Default height** = `rack.height`, else the project template `ru` (`doc.templates`),
   else the library template `ru` via `ctx.api.template()` (fetched and cached while the
   unracked list renders), else 1. A library template with `width: half` defaults
   `side: left`.
4. **`placeOps` returns `[]`** when the device does not fit and `force` is not set. The
   view checks `fits` first and refuses the drop with a toast. An Alt-drop on an occupied
   RU passes `force`; out-of-range drops are always refused.
5. **Inventory rows come from the live doc** (`inventoryRows`), not
   `GET …/schedules/inventory`. Pending local ops then show immediately, and the fields are
   identical to the inventory schedule. CSV download uses the server URL when `ctx.api`
   exists, else a client-side Blob. §6.7 says inventory reads rows from the server; this is
   the one place I chose liveness. Schedules do read from the server.
6. **Schedules in server mode.**
   - Edited rows update in place right away.
   - The table re-fetches on store `revision` events (after the change queue flushes) and on
     `doc` events from `load`/`remote`.
   - Tag preview: if `base_revision` no longer equals `store.revision` at confirm time, the
     UI re-previews instead of committing.
   - Harness mode uses a local §4.8 implementation (`assignTagsLocal`, schedules.js only).
     It gives the exact FR-CAB-02 result on the fixture.
7. **Uploads.** `ctx.api.upload(project, 'floorplans', files, {room, name})` writes on the
   server. The view then applies `put floorplans/<id>` with `store.applyRemote` and calls
   `store.setRevision(res.revision)` when that is ahead, so the plan shows without a
   reload. Inventory photo uploads do the same for `attachments`. If the shell prefers to
   reload the doc after uploads, these calls are harmless (the put is skipped when the id
   already exists).
8. **"Also delete files" on plan delete is not offered.** The view deletes only the
   floorplan entity and says the files are kept. W5's `api.deleteFile` exists now and could
   be wired in later.
9. **Layer toggles** commit `hidden_layers` and swap the image URL to `…/image?hide=A,B`
   (`api.floorplanImageUrl` joins the array). In the harness there is no server render, so
   the image does not change; the popover says so.
10. **Plan image backdrop.** Plans whose `source.kind` is `dxf` sit on a dark backdrop,
    because W2 renders DXF with light `#c8cfdd` strokes on a transparent background. Other
    plans sit on white.
11. **Marker tap.** A tap calls `ctx.select({type: 'device', id})` and opens a small popover
    with Details (`ctx.openInspector`), Open device page (`p/<project>/d/<device>`) and
    Remove. Keyboard: arrows move the marker 0.5% (Shift 2.5%), Delete removes it, Enter
    opens it. With a tool active, Enter adds a point at the centre crosshair.
12. **BOM rows include spares** regardless of the state filter (§4.4.6). Retired devices
    follow the state filter. The fixture shows 6498.00 USD only with "All rooms", because
    the spare lives in shared inventory (`room: ""`).
13. **G4 command on Node 26.** `node --test tests/js` fails on Node 26: the directory is
    treated as a module path. `node --test tests/js/*.test.mjs` passes (120/120 when last
    run). This is for T2/QA to look at.
