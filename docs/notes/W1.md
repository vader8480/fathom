## Interpretations (spec ambiguities, decided literally where possible)

1. **`parse_port_text` and `×`** (§4.6.4). The text lists `"line in L/R ×4"` as *opaque*, but rule 2 as written
   would make it an *index* (the character before `4` is `×`, not one of `/ . : &`). Appendix G's numbering
   (cables `c-0001…c-0049` for links 0–14, `c-0050` for link 15) only works when it is opaque, so `×` (U+00D7)
   is added to the opaque-before set.
2. **`io` side** (bidirectional links): an `io` side accepts ports of any direction. Generated generic groups for
   an `io` side are named `I/O`; the empty-side rule still uses `Out` / `In` by from/to side (dir `io`).
3. **Single opaque port** gets `channels = max(1, count)` always (literal §4.6.4), so `channels: 1` can appear.
   Expanded template / declared ports only carry `channels` when > 1 (§4.4.3).
4. **Opaque side with K > 1**: the existing-name and trailing-token matches run first; the K-port group replaces
   only the final "create single port" step.
5. **`save_doc(..., base_revision=None)`** skips the concurrency check (CLI / internal callers). The HTTP API
   itself returns 428 when neither `If-Match` nor `base_revision` is sent.
6. **Baseline revision.** A project without history (new, v0.2 or v1 file) has stored revision 0 (or whatever
   its file says). On its first write the pre-change doc is recorded as revision `max(1, stored)` (source
   `migrate` for v1 files, else `put`), and a client `base_revision` equal to the stored revision is treated as
   that baseline. So: create → GET `ETag: "r0"` → PUT `If-Match: "r0"` → revision 2 (history has 1 and 2).
7. **Validation blocking** only rejects *new* errors (errors not already present in the stored doc). A migrated
   v1 file with a pre-existing dangling link can still be edited; introducing a new error returns 422.
8. **Empty writes** still create a revision (FR-HIST-01 "every successful write").
9. **`normalize` scope**: empty-value pruning applies to entities in collections only; `meta` / `settings` are
   copied as-is (an empty `meta.intro` is meaningful: it suppresses the v1 default intro).
10. **v1 `PUT /api/projects/<n>`** saves `migrate(body)` through `save_doc` without a concurrency check
    (v0.2 had none), source `put`.
11. **CSRF**: a `POST` with no body and no content type also needs `X-Fathom: 1` (strict reading of FR-SEC-03).
12. **`save_project` on a v2 folder** (v0.2 API used by the CLI) no longer overwrites with v1 JSON: when the doc
    is v1-expressible it stores `migrate(project.to_dict())` as a revision (source `cli`); otherwise it only
    carries `meta` and the default room's `imports` into the doc.
13. **Samples are read-only**: `save_doc` / `apply_changes` / `add_attachment` refuse folders under
    `fathom/samples/` (PermissionError → 403), so nothing can write into the frozen RRC sample.
14. **External devices in `flow_project`** (cables crossing rooms) become auto nodes in auto groups
    `ext-left` / `ext-right` labelled "Other rooms", placed in the outermost column of that side.
15. **Share links** (P1) are stored per project in `shares.json`; `/s/<token>/…` re-dispatches to the `/p/…`
    viewer handlers. Expired (`expires` < now, ISO compare) and revoked tokens → 404.

## Calls into other units (lazy, inside handlers)

Per §7.4.5. Optional keyword arguments are passed through a signature filter (`server._compat`) so v0.2
signatures of `render_html` / `write_build` keep working until W5 / W2 land the new keywords. `export.device_url`
has a local fallback (`<base>/p/<project>/d/<device>`, FR-EXP-04). `validate_doc` calls `racks.validate_racks`,
`network.network_problems`, `dmx.dmx_problems` when importable and otherwise runs minimal built-in checks
(`rack_unknown`, `rack_out_of_range`, `bad_ip`, `bad_subnet`, `dmx_range`).
