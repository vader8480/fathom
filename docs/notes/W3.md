# W3 — Patch view: implementation notes

Files (all W3-owned per §7.2): `fathom/static/js/patchview-core.js`, `fathom/static/js/patchview.js`,
`fathom/static/css/patchview.css`, `fathom/static/dev/patchview.html`, `fathom/static/dev/fixture-gen.js`.

## Design

- **Rendering**: HTML cards (absolutely positioned, `transform: translate`) plus one SVG layer of
  `<path data-cable>` wires, all inside `div.pv-world`, which carries the single pan/zoom transform
  (`translate3d(x,y,0) scale(k)`). First render builds two HTML strings (cards, wires) and sets
  `innerHTML` once each.
- **Incremental updates**: store `doc` events rebuild the (pure, ~3 ms at 150/600) scene, then diff
  per-card HTML strings and per-wire signatures and replace only what changed. Full re-render when
  `touched` has > 50 refs, a non-device/cable ref, or `source: 'load'`.
- **Drag**: only wires attached to moved cards are recomputed (`core.updateWires`), in
  `requestAnimationFrame`. Measured `lastDragFrameMs` ≤ 0.4 ms on the busiest 150/600 card.
- **Hit testing** is geometric (`core.hitTest`) on world coordinates, not DOM targets, so mouse, pen
  and touch share one path. The DOM uses the same geometry numbers as the core (`GEOM`, rowH 32 on
  `(pointer: coarse)`), and the CSS dot offsets account for the 1 px card border.
- `patchview-core.js` has no imports (not even `model-core.js`), so T2 can test it standalone. It
  carries its own `slug`, direction rules (`orient`, the §4.4.4 direction subset) and viewport math.
  `patchview.js` uses `model-core.js` for every op builder (`connectOps`, `repatchOps`,
  `disconnectOps`, `renameOps`, `deleteDeviceOps`, `duplicateDeviceOps`, `addDeviceFromTemplateOps`,
  `setPortsOps`) and `canConnect` (warning/error toasts).

## Choices where the spec leaves room

- **Port dot vs wire end** (same spot on a connected port): dragging an `in` port with exactly one
  cable grabs that wire's end (re-patch). The ends of the *selected* wire are always grabbable within
  12 screen px. Dragging an `out`/`io` dot always starts a new wire (fan-out).
- **Keyboard ports**: port rows are `tabindex=-1` (Tab stays card-to-card, FR-PV-09). On a focused
  card, `P` or `Alt+↓` enters its ports; `↑/↓` moves between rows, `Enter`/`F2` renames the label, `C`
  starts a connection (arrows cycle compatible targets, nearest first; Enter commits; Esc cancels),
  `T` / `Shift+T` traces down/upstream, Esc returns to the card. `D` duplicates the focused card,
  `Shift+F10` / ContextMenu opens the menu. Described in the viewport's `aria-describedby` text.
- **Double-click/tap** is detected in the pointer pipeline (two taps < 380 ms, < 12 px), not with the
  `dblclick` event, because iOS does not reliably fire `dblclick` under `touch-action: none`.
- **Filters**: discipline/status/text/showUnconnected go through `store.setFilter` (shared with the
  patch table). "All rooms", "Network routes" and "Snap" are view-local state (`getState`/`setState`).
  A device passes a discipline chip if its own discipline or any port medium's discipline is selected
  (ATEM shows under Video and Audio). Wires pass if the cable medium's discipline or `carries`
  intersects the chips.
- **External ghosts**: only for devices in *another room* cabled to an in-room device (never for
  devices excluded by discipline/system/status filters).
- **Group drag** snaps the lead (grabbed) card to the 8 px grid and moves the group rigidly; the
  commit only rounds (`moveOps(doc, pos, 0)`). One merge op per moved device, one undo step.
- **Trace from here**: discipline = the port medium's discipline (`other` → no filter); device-level
  start uses `dev:*`. The context menu offers "Trace from here" (downstream) and "Trace upstream".
- `traceLocal` adds the `dev:*` virtual node only for devices that actually have a device-level
  endpoint (cable or overlay route), or for a `dev:*` start. Wiring `dev:*` into every device would
  let a trace jump from any port to every other port of the same device, breaking FR-TRC-05.
- `traceLocal(…, {paths: true})` also returns `paths` (§6.9.4 ordering), and `pathText(doc, path)`
  renders the §6.9.4 text. On the fixture the first downstream path from `audio-rack-1:analog-out-4` is
  `Audio Rack 1 · Stream → ATEM Mini · Stream → USB Stream Out → Restream`. These are for W5's offline
  assistant fallback; optional.
- `autoLayout(doc, ids, vocab, opts)` accepts the origin as `opts.origin` **or** `opts.x/opts.y`
  ("origin opts" in §6.5 is ambiguous). Without `opts.heights` it sizes cards from the doc's cabled
  ports so that collapsed columns match the rendered height.
- `moveOps(doc, positions, grid)` takes an optional third arg (default 8; 0 = no snap).
- Extra exports beyond §6.5 (additive): `ZOOM_MIN/MAX`, `slug`, `portsOf`, `mediumInfo`, `carriesOf`,
  `mediumDiscipline`, `deviceDiscipline`, `disciplineInfo`, `portLabelOf`, `modelLine`, `deviceTitleOf`,
  `wireControls`, `wireDistance`, `wireAnchors`, `boundsOf`, `updateWires`, `orient`, `arrangeOps`,
  `newPort`, `clampK`, `screenToWorld`, `worldToScreen`, `zoomAt`, `fitView`, `buildTraceGraph`,
  `pathText`. Scene objects carry extra fields (`cardById`, `wireById`, `wiresByDevice`, `wiresByPort`,
  `autoPositions`, wire `a`/`b` anchors, card `title/model/discipline/roomName/placed`). `hitTest`
  can also return `type: 'more'` (the "+N more" row).
- Extra toolbar controls: `#pv-save-arrangement` (FR-PV-12 "Save arrangement", shown only when
  auto-positioned cards exist) and `#pv-snap` (FR-PV-03 snap toggle).

## Harness (`dev/patchview.html`)

- The page has **no inline script**: the server sends `script-src 'self'` on `/static/dev/*` too.
  The harness boot code is `bootPatchviewHarness()` in `fixture-gen.js`. It auto-runs only when the
  page's `<html data-harness="patchview">` imports it; in Node, importing the file has no side effects.
- `fixture-gen.js` imports `model-core.js` and `patchview.js` **statically**. With dynamic `import()`,
  headless Chrome's `--virtual-time-budget` raced the module fetches and `data-smoke` was
  intermittently missing.
- Vocab: when served over http(s), `../../api/v2/meta` is used, else the embedded `HARNESS_VOCAB`
  snapshot (`vocab.as_dict()` kinds/media/disciplines/brands/statuses, 2026-10-21).
- Query params: `smoke=1`, `devices=N&cables=M[&seed=S]`, `overlay=1` (demo Dante routes + import
  labels), `readonly=1`, `room=<id>` (`room=` = shared inventory).
- **`file://` in Chrome needs `--allow-file-access-from-files`.** Chrome refuses ES modules and
  XHR from `file://` origins otherwise, and no page-side workaround exists. Served at
  `/static/dev/patchview.html` it needs nothing.
- Under `--virtual-time-budget`, `performance.now()` barely advances, so `renderMs` in the
  virtual-time smoke reads 0–90 ms. Real-time measurement (CDP, no virtual time): fixture ~5 ms,
  150/600 ~59 ms on this Mac.

## Touch sizing (QA D11 fix)

- Under `(pointer: coarse)` the layout row pitch is `COARSE_ROW_H = 36` (exported by the core), so each
  row box is 32 px with a 4 px gap. `patchview.js` passes it as `geom.rowH`, and it always writes
  `--pv-row` inline from the same geometry, so CSS row boxes and wire anchors cannot disagree. The
  earlier "32 px" was the pitch; the box rendered 28 px.
- Every button in the toolbar, filter chips and context menu gets `min-width`/`min-height: 44px`
  (`flex-shrink: 0`) under a coarse pointer. Port dots keep a 44 px `::after` hit area and a 22 px
  geometric hit radius in `hitTest`. Desktop sizes are unchanged.

## Open questions / integration notes

1. **Gate G4 on Node 26**: `node --test tests/js` fails ("Cannot find module …/tests/js") because
   Node 26 treats a directory argument as a module path. `node --test tests/js/*.test.mjs` runs all
   120 tests (all pass). T2/QA may want the glob form in §8.1.
2. `store.highlighted` is the getter name for the current highlight in W5's store (the spec's
   §6.2 table lists `highlight` only as a method). The view reads `store.highlighted`.
3. The view relies on `doc` event `detail.touched` (W5 provides it) and on
   `store.filter.showUnconnected` (W5's default filter has it).
4. ⌘Z / ⇧⌘Z / Ctrl+Y are handled on the view root with `preventDefault()`; the shell's global
   handler already skips `defaultPrevented` events, so there is no double undo. The view does not
   announce undo/redo; the shell does.
5. Arrowheads (FR-PV-02 "optional (setting)") are not implemented: no setting key is specified and
   per-colour SVG markers would need `context-stroke` (unsupported in Safari 15).
6. FR-PV-11 "Add gear placed at viewport center": the shell's `ctx.pickTemplate({})` is called with an
   empty filter. The template comes back in §4.5 form and goes to `addDeviceFromTemplateOps` with
   `{room, x, y, vocab}`.
7. Dragging an external ghost card moves that device's `patch` position, which is shared by all
   rooms (one `patch` field per device).
